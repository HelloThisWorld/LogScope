# LogScope v0.5 Implementation Plan — Preflight Record (BLOCKED)

Updated: 2026-07-31 (preflight session)
Branch: `feature/logscope-v0.5` (from `main` @ `766c1b2`, the PR #5 merge)

v0.5 goal: the Bounded Agent Query Interface — a versioned, transport-neutral
Agent Query Protocol (pre-stable `v1alpha1`), a machine-first local CLI, an
optional loopback-only authenticated HTTP service, a single operation
registry of bounded read-only operations (workspace/dataset discovery,
search, aggregate, facet, timeline, context, record.get, pattern.*,
comparison.run, correlation.find, finding.get, evidence.get, report.get),
field-level disclosure profiles, capability tokens, metadata-only audit,
and a deterministic end-to-end agent investigation demonstration.

**Status: the mandatory preflight gate exposed the same major missing
prerequisites that blocked v0.4, plus v0.4 itself. v0.5 implementation is
BLOCKED until v0.3 is completed and v0.4 is implemented and accepted. No
v0.5 protocol, CLI, HTTP, or policy code was written in this session — by
milestone rule, an Agent API must not be published over capabilities that
do not exist or cannot be disclosed safely.**

## Preflight decision (per milestone rules)

The v0.5 milestone rules distinguish narrow gaps ("fix … when clearly
required … do not redesign completed foundations") from major
prerequisites ("If a major prerequisite such as … evidence/report
revisioning, disclosure projection, workspace persistence, or safe
locking is absent, **stop before publishing an Agent API that can return
inconsistent or unsafe results**"), and additionally forbid silently
reimplementing v0.0 through v0.4.

The gaps found are not narrow regressions. They are one entire milestone
(v0.4 deterministic analysis) plus six-plus unstarted v0.3 work packages:

| Missing capability | Milestone debt | v0.5 work it blocks |
|---|---|---|
| Deterministic analysis: patterns, stack fingerprints, comparison, correlation, findings, migration `0004`, stable run/result identities | all of v0.4 (WP1–WP9) | operations `pattern.list`, `pattern.examples`, `comparison.run`, `correlation.find`, `finding.get`; analysis capability discovery; the mandatory end-to-end demonstration (first-increased error pattern between baseline and suspect windows) |
| Report generation + exact report revisions | v0.3 W5 | `report.get`; report-content disclosure; e2e report-metadata resolution |
| Shared disclosure/redaction projection | v0.3 W6 | **all of WP6** — the Agent disclosure profile must wrap the existing projection, and every operation (incl. `search`, `record.get`, `evidence.get`) applies it before predicates/sort/facets/examples/errors; building it fresh inside v0.5 would create the second implementation the invariants forbid |
| Timeline model/UI | v0.3 W4 | `timeline` operation `investigation` mode |
| Investigation + evidence UX | v0.3 W3 | WP7 Agent Access UX host surfaces; UI-vs-API cross-surface equivalence evidence |
| Portable case bundle | v0.3 W7 | honest bundle-excluded/snapshot-only integrity states in `evidence.get`/`report.get` |
| 5M benchmarks, reliability passes | v0.3 W8 | WP8 baselines the v0.5 benchmarks extend |
| v0.3/v0.4 sweeps, acceptance matrices, releases | v0.3 W9/W-R, v0.4 WP9 | v0.5 gate 1 ("actual v0.4 acceptance report") and gate 2 ("existing valid v0.4 workspace" under a frozen released schema) |
| Graphical setup extractor + payload byte-equivalence | inherited v0.2 gate 19 | v0.5 packaging gates (both artifacts from one payload, CLI + schemas included in both) |

Of the seventeen operations in v0.5 WP3, seven (`pattern.list`,
`pattern.examples`, `comparison.run`, `correlation.find`, `finding.get`,
`report.get`, `timeline` investigation mode) have no baseline capability
at all, and every operation depends on the missing disclosure projection
(P15/P16). The mandatory end-to-end acceptance demonstration requires
patterns + comparison + correlation + findings + evidence + report in one
flow — impossible without v0.4 and v0.3 W5/W6.

Building v0.5 now would force one of two outcomes the prompt forbids:
silently implementing most of v0.3 and all of v0.4 inside this milestone,
or shipping an Agent API whose analysis/report/disclosure operations are
placeholders — a protocol advertising capabilities that do not exist,
with no shared projection to keep hidden fields hidden. The correct
action is to stop, keep the repository valid and green, record this
preflight, and hand off a remediation path.

What was deliberately **not** done: no protocol schema, operation
registry, CLI crate, HTTP listener, token/capability code, disclosure
wrapper, audit table, or migration was added; no dependency was
introduced; no version string changed; no v0.2–v0.4 code was rewritten.
The only change in this session is this document.

## Recorded repository facts and decisions for the resumed session

These are verified repository facts (not design work), recorded so the
resumed milestone does not re-derive them:

- **Windows executable names:** the GUI binary is `logscope.exe`.
  Windows filenames are case-insensitive, so the CLI **cannot** be
  `logscope.exe`/`LogScope.exe`; the resumed session should ship a
  distinct binary (the milestone prompt's suggested `logscope-cli.exe`)
  unless an ADR establishes a safe multi-mode single binary.
- **Protocol versioning:** no repository convention exists for an agent
  protocol version; the milestone default `v1alpha1` applies. v1 must
  not be declared stable before LogScope v1.0.
- **Schema generation:** ts-rs covers Rust→TypeScript only. Shipping
  machine-readable JSON Schemas requires a new generation/conformance
  decision in WP1 (single source, drift-failing CI).
- **Concurrency:** no cross-process lock/lease exists (see matrix
  addendum); `workspace_busy` semantics must be designed and proven, not
  assumed, before the CLI ships.
- The initial hard-budget table, operation list, error-code catalog, and
  security requirements live in the v0.5 milestone prompt, which remains
  the specification for the resumed implementation; nothing was descoped
  by this record.

The plan sections the milestone contract requires for implemented work —
protocol/operation-registry/request/response/cursor/error/capability/
disclosure schemas; CLI transport decisions beyond the binary name;
loopback lifecycle/authentication/allowlist/rate-limit/revocation design;
the operation-by-operation limit table; threat model; budgets; benchmark
environment — are intentionally **not authored in this session**. They
must be designed against the completed v0.3 disclosure/report/bundle
contracts and the completed v0.4 analysis identity contracts; authoring
them against a moving baseline would bake in guesses that the protocol's
compatibility rules then freeze. They are the first deliverable of the
resumed milestone (WP1 design pass), after remediation.
