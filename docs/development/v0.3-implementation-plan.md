## Schema design (migration `0003_investigations`, workspace schema v3)

One forward-only migration, applied in one transaction by the existing
runner. **Pre-release iteration policy:** schema v3 has shipped in no
released build; until 0.3.0 is released, 0003 may be amended in place on
this branch. After release it is frozen like 0001/0002.

Conventions carried over: STRICT tables, TEXT ULID-free opaque IDs with
type prefixes, RFC3339 TEXT wall-clock stamps, unix-nanos INTEGER event
instants, `*_json` typed payload columns.

ID scheme (UUID v4, never content hashes — identity is independent of
title/path/row/order): `inv-` investigation, `hyp-` hypothesis, `item-`
note/task/finding/question, `iscope-` scope ref, `ev-` evidence, `evg-`
evidence group, `mark-` timeline marker, `rep-` report definition, `art-`
generated artifact, `red-` redaction profile, `bnd-` bundle export,
`bimp-` bundle import record.

Tables (full DDL in the migration file):

- `investigations` — schema_version, title, description, status
  (`open|investigating|mitigated|resolved|archived`), severity (generic
  documented scale `sev1..sev4|none`), owner_text (exactly as typed; never
  inferred from OS/git), tags_json, created/updated/status_changed stamps,
  optional incident/mitigation/resolution instants + relevant window
  (half-open nanos), `revision` (optimistic concurrency token).
- `investigation_scope_refs` — typed rows: `dataset` (dataset_id +
  captured `dataset_revision` fingerprint), `resource_selector`
  (selector_json), `saved_query` (saved_search_id), `embedded_query`
  (query_json w/ language_version), `time_window`, `label`. Fail honestly:
  unresolvable targets are reported, never name-matched.
- `hypotheses` — statement, rationale, state
  (`unverified|supported|rejected|confirmed` — all transitions manual),
  position, revision. `hypothesis_evidence` join table for linked evidence.
- `investigation_items` — kind `note|task|finding|question`; content;
  task_status `todo|doing|done|dropped`; question_status
  `open|answered|deferred`; `authored_by_user` = 1 for every v0.3 row;
  reserved `finding_provenance_json` (NULL in v0.3) lets deterministic
  v0.4 findings carry rule/calculation provenance without changing manual
  findings' meaning; position; archived flag; revision.
- `evidence` — envelope: envelope_version (=1), kind
  (`event|selection|query|explorer_group|histogram_interval|item_ref`),
  signal (`log|manual`), title, annotation, relevance,
  captured_investigation_revision, group_id, position,
  supersedes_evidence_id, archived (normal removal = archive + history
  tombstone; hard delete is not a UI operation), resolver_state +
  resolver_detail_json + last_verified_at, `reference_json` (typed live
  canonical reference), `snapshot_json` (bounded captured snapshot),
  revision. Live reference and captured snapshot are separate columns and
  never rewritten by verification.
- `evidence_groups` — named local ordering groups.
- `timeline_markers` — kind
  (`deployment|config_change|operator_action|custom`), label, description,
  at_nanos (UTC; NULL = undated section), optional end_nanos (bounded
  interval), original_tz_offset_min + original_time_text preserved exactly
  as entered, archived, revision. Markers are always manual.
- `report_definitions` — title/subtitle, sections_json (ordered; narrative
  sections carry user-authored content or explicit `unknown`),
  selected_evidence_json (`[{evidence_id, revision}]` — exact revisions),
  selected_markers_json, redaction_profile_id + captured profile version,
  options_json (display tz, excerpt bounds, path policy), revision.
- `report_artifacts` — immutable generation records: format
  (`markdown|html`), destination, snapshot_json (the consistent
  investigation snapshot: entity revisions, resolver states at capture,
  language/envelope/schema/app versions, tz, profile version), SHA-256,
  byte_size, status (`completed|failed|cancelled`), created_at.
- `redaction_profiles` — name, version (bumps on rule change), rules_json
  (ordered typed rules), posture_json (path policy, bounds, allow/deny).
- `bundle_exports` / `bundle_imports` — immutable export records
  (manifest_json, SHA-256, status) and import provenance in the *destination*
  workspace (original path, bundle checksum, manifest, detail).
- `case_history` — the single non-destructive history/activity ledger:
  (investigation_id, entity_kind, entity_id, revision, action,
  payload_json = full entity state after the action, detail_json,
  created_at). Every material mutation inserts its history row in the same
  transaction. No OS identity is captured anywhere. Content hashes, when
  present, are labeled integrity aids — never signatures/authorship proof.

Rollback safety: the migration is a single transaction (rusqlite `tx`),
so a failure leaves schema v2 intact and reopenable by 0.2.0 builds.
Forward-only policy unchanged (`SchemaTooNew` guards downgrades). The
migration only CREATEs new tables — it rewrites no v2 data and touches no
Parquet, so a migrated-then-rolled-back workspace loses nothing.

Concurrency: every update statement is `... WHERE <id> = ? AND revision = ?`;
zero affected rows surfaces `case/stale-revision` (structured conflict), the
UI reloads and re-applies. Last-write-wins is never silent.

## Dataset revision fingerprint

v0.3 needs a durable "dataset revision" for evidence capture. Definition:
`dsrev-<hex>` = `stable_id` digest over the dataset's published segment set
(sorted `(segment_id, row_count, byte_size)` triples) + dataset_id +
storage schema version. Computed from `segments` on demand; captured into
evidence/scope refs at pin time. Properties: append-only imports change the
fingerprint (drift is visible), identical sets reproduce it byte-for-byte,
and it needs no new table. It is an integrity aid, not a signature.

## Evidence resolution and integrity-state decision table

One resolver (app layer), batched (single id-set lookup per dataset via the
existing temp-table pattern — no per-evidence queries), bounded, cancellable
via the existing cancel registry, and read-only: verification NEVER rewrites
`snapshot_json`, never re-imports, never mutates references. Updating a
reference is an explicit user action producing a new revision or a
superseding evidence item.

States (stored in `evidence.resolver_state`; details in
`resolver_detail_json`):

| State | Condition (first match wins per kind) |
|---|---|
| `unverified` | never verified, or verification cancelled before this item |
| `unsupported_reference_version` | envelope_version / query language_version newer than this build understands |
| `broken` | canonical reference unresolvable AND captured snapshot absent/undecodable |
| `dataset_revision_unavailable` | referenced dataset deleted, or recorded `dsrev` cannot be recomputed (segments gone) |
| `source_missing` | canonical record resolves; registered source file absent on disk |
| `source_changed` | source file present but BLAKE3/content identity ≠ captured fingerprint (size fast-path, hash confirm) |
| `canonical_available_source_unavailable` | canonical data resolves; original bytes cannot be checked (no registered path — e.g. bundle-imported subset, or managed copy absent) |
| `partially_resolved` | bounded selection: some IDs resolve, some do not (per-id detail recorded) |
| `query_drift` | query/group/interval evidence: query still validates + runs, but result metadata (count state, boundary hashes) ≠ captured |
| `verified` | reference resolves and every expected fingerprint/revision matches |

Secondary conditions that do not change the primary state are recorded in
`resolver_detail_json` (e.g. dataset revision advanced while the pinned
record still verifies; profile/parser version drift). Distinct conditions
are never collapsed into a green/red boolean; the UI renders each state
with text + icon (never color alone). Hash scope is documented: source
fingerprints are full-file BLAKE3 (`source_files.content_hash`) with a
size fast-path; absence of a checkable hash is its own visible state, and
nothing weaker is presented as full verification.

## Report, redaction, and bundle schemas (contract summary)

- Report sections: `summary, impact, symptoms, timeline, hypotheses,
  evidence, root_cause, resolution, validation, follow_up` — narrative
  sections are user-authored on the report definition (empty / omitted /
  explicit `unknown` per documented rule; nothing synthesized); timeline /
  hypotheses / evidence sections are projections of selected data at exact
  captured revisions, keeping hypothesis states and integrity warnings.
- Markdown: deterministic UTF-8, LF line endings, no raw HTML passthrough
  (everything escaped/coded), dynamic fence sizing so embedded backticks
  cannot escape, stable `ev-` anchors, explicit truncation/approximation/
  missing-source labels, no absolute local paths by default.
- HTML: one self-contained file — embedded CSS only, zero scripts/forms/
  iframes/objects/remote anything, restrictive CSP meta
  (`default-src 'none'; style-src 'unsafe-inline'`), all content escaped by
  context, imported URLs/paths never become links, charts (if any) are
  static inline SVG/tables without handlers. Readable with JS disabled
  because no JS exists.
- Redaction = export projection shared by MD/HTML/bundle: rules (field
  omission, masking with fixed token, exact replacement, bounded safe-regex
  replacement, provenance path policy omit|basename|include, field
  allow/deny lists, excerpt/record bounds, optional deterministic
  pseudonymization labeled as such). Never mutates canonical data. Preview
  is generated by the SAME projection as final bytes and is invalidated by
  any input change. Heuristic secret detection, if any, is labeled
  best-effort warnings only.
- Bundle `.logscope-case` = standard ZIP: `manifest.json`,
  `investigation/*.json`, `evidence/evidence.jsonl`, `queries/queries.json`,
  `timeline/markers.json`, `data/logs.parquet` (declared closure subset),
  `excerpts/…` (explicit only), `reports/report.{md,html}`,
  `checksums.sha256`. Manifest: bundle schema version, min compatible
  capability contract, investigation identity + captured revision, entry
  list w/ type/size/SHA-256, evidence/query schema versions, dataset +
  reproduction-scope descriptors (`full_within_declared_dataset_revision |
  included_subset_only | snapshot_only`), disclosure summary, explicit
  inclusion decisions, truncation states, no absolute paths. Checksums =
  integrity detection, not authorship. Import: strict manifest validation,
  entry-path hardening (reject abs/traversal/drive/ADS/reserved/NUL/dup/
  case-collision/symlink/device), size/ratio/count/depth limits, checksum
  verification, staging + transactional import into a NEW isolated
  workspace, ID-conflict remap-or-refuse, provenance recorded, unsupported
  versions fail actionably. Bundled reports are never auto-opened.

## Disclosure/redaction threat model (summary)

Assets: log content (may contain credentials/PII), local paths/usernames,
dataset shape, investigation narrative. Adversary for outbound artifacts:
the *recipient* (curious or hostile) and any renderer they use; for import:
a hostile bundle author. Mitigations: default-closed inclusion (nothing
leaves without explicit selection), projection-equality between preview and
final bytes, no hidden payloads (tests parse final HTML/ZIP and assert
excluded values absent), inert artifacts (no scripts/links/active content),
hardened import validation (above), and honest labels for every omission/
truncation/pseudonymization. Out of scope (documented, not implied):
cryptographic authenticity, non-repudiation, chain of custody, protection
from a malicious local administrator, bundle encryption/signatures
(deferred by milestone).

## Performance / privacy / security / compatibility risks

| Risk | Mitigation |
|---|---|
| N+1 evidence resolution | one batched id-set lookup per dataset (temp-table pattern), measured in benchmarks |
| Evidence snapshots bloat webview | list virtualization; snapshots paged by evidence id; bounded snapshot sizes at pin time |
| Report/bundle materializes datasets | streamed writes through staging; closure planner enforces row/byte limits before writing |
| Hostile log text in reports | context escaping + fence hardening + HTML parser tests + zero-network test on opened artifact |
| Redaction bypass via metadata | single projection for preview+final; ZIP/HTML scanned for excluded values in tests |
| Hostile bundle import | validation-before-extraction, staging isolation, limits, checksum enforcement (WP7 test corpus) |
| Migration risk on real workspaces | additive-only 0003 in one transaction; v2 fixture round-trip test; recovery on interrupted migration |
| Concurrency conflicts | optimistic revisions + structured `case/stale-revision`; no silent last-write-wins |
| Windows-only leakage into shared core | `logscope-case` stays path-neutral (relative paths, forward-slash entry names in bundles) |
