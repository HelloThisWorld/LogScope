Updated: 2026-08-01 (preflight session)
Branch: `feature/logscope-v0.8` (from `origin/main` @ `79ca992`, the
PR #8 merge of the v0.7 preflight record)

v0.8 goal: Tracing Lite and Unified Telemetry Investigation — bounded
trace search over a Local OTel Session at an exact dataset revision,
deterministic trace reconstruction (waterfall, parent-child tree, span
links, quality/completeness/sampling honesty), exact log/exemplar
navigation, Correlated/Probable cross-signal relationships without
causation claims, span-derived RED summaries, shared time-range
overlays and baseline/suspect comparison, versioned local dashboards,
active-session deterministic findings, trace/cross-signal evidence in
reports and `.logscope-case` bundles, and six read-only Agent
operations (`trace.search`, `trace.get`, `span.list`, `trace.logs`,
`trace.metrics`, `signal.summary`).

**Status: the mandatory preflight gate exposed the same debt chain that
blocked v0.4, v0.5, v0.6, and v0.7 — now five milestones deep. v0.8
implementation is BLOCKED until v0.3 is completed and v0.4, v0.5, v0.6,
and v0.7 are each implemented and accepted. The v0.8 milestone
"productizes spans already stored by v0.7", and there are no
v0.7-stored spans: no Local OTel Session, no watched-folder or
authenticated-receiver ingestion, no durable acceptance, no
active/immutable signal segments with exact revisions, no production
typed-column span storage, and no bounded span query repository exist.
Five of the eight majors named by v0.8's own stop rule are absent
(lossless span storage, exact revision snapshots, bounded span
querying, deterministic correlation, disclosure parity). No v0.8
trace-domain, index, reconstruction, UX, RED, correlation, dashboard,
finding, evidence, report, bundle, or Agent code was written in this
session — building Tracing Lite against today's tree would require
first inventing the v0.7 span substrate, the v0.6 metric surface, the
v0.5 Agent protocol, the v0.4 correlation engine, and the v0.3
report/redaction/bundle contracts, exactly the incompatible parallel
system the stop rule forbids.**

## Preflight decision (per milestone rules)

The v0.8 milestone rules distinguish narrow gaps ("fix narrow
regressions or small missing prerequisites … do not redesign completed
ingestion, query, analysis, evidence, metric, Agent, or packaging
foundations") from major prerequisites ("If a major prerequisite such
as lossless span storage, exact revision snapshots, shared
Resource/Scope identity, safe identifier representation, bounded span
querying, deterministic correlation, disclosure parity, or recoverable
migrations is absent, **stop before building incompatible trace
behavior**"), and additionally forbid silently reimplementing v0.0
through v0.7, bypassing the canonical span repository with a UI-only
scan, or declaring structural completeness the stored data cannot
support.

The gaps found are not narrow regressions. Directly from the stop
rule's named list: **lossless span storage at the production
typed-column contract is absent** (P7/P11 — spike JSON-flattening,
no invalid-original states), **exact revision snapshots spanning
active and closed segments are absent** (P12), **bounded span querying
is absent** (P13), **deterministic correlation is absent** (P14 — all
of v0.4), and **disclosure parity is absent** (P17 — v0.3 W6 never
built). Around them sit four unimplemented milestones plus seven
unstarted v0.3 work packages:

| Missing capability | Milestone debt | v0.8 work it blocks |
|---|---|---|
| Local OTel Session, watched folders, authenticated receivers, durable acceptance, spool/ledger/checkpoints, active/immutable segments, exact publication revisions, production typed-column span storage, retention | all of v0.7 | the entire span substrate WP1–WP5 productize; trace scope/revision identity; incremental snapshots (WP14); "spans already stored by v0.7" do not exist |
| Canonical metric pipeline, Metric Query Definition v1, Metrics Explorer, exemplar storage/disclosure, five `metric.*` Agent operations | all of v0.6 | exemplar→trace navigation (WP7); trace-range metric overlays (WP9); metric panels (WP10); metric thresholds in findings (WP11); `trace.metrics`/`signal.summary` (WP13) |
| Agent Query Protocol v1alpha1 (registry, capabilities, cursors, disclosure, budgets, tokens, audit, CLI, loopback HTTP) + cross-process workspace locking | all of v0.5 | all six v0.8 Agent operations (WP13); cross-surface equivalence gates 76–87; safe concurrent access (P21) |
| Deterministic analysis: patterns, comparisons, correlation engine, findings, confidence classes, semantic fingerprints, cache invalidation | all of v0.4 | Correlated/Probable relationships (WP8); baseline/suspect comparison (WP9); finding model (WP11); confidence contract reuse everywhere |
| Reports, shared redaction/disclosure projection, portable `.logscope-case` bundles, evidence/timeline UX, 5M benchmarks, release prep incl. `tools/logscope-setup` | v0.3 W3–W9 + W-R | evidence kinds 1–8 rendering (WP12); redacted offline reports; bundle reproduction closure; disclosure-aware Agent responses; regression gates 92–94; packaging gates 98–99 |

Of v0.8's sixteen work packages, none has a complete host to extend:
WP1 (trace domain) would freeze migration numbers and revision shapes
that the v0.4–v0.7 chain defines; WP2/WP3 (index, reconstruction) have
no production span storage or revision snapshots beneath them; WP6–WP9
(RED, navigation, correlation, overlays) require the v0.4 engine and
v0.6 services; WP10–WP11 (dashboards, findings) bind query definitions
that do not exist for two of three signals; WP12 (evidence/report/
bundle) extends v0.3 contracts never built; WP13 (Agent) extends a
protocol that does not exist; WP14–WP16 (incremental behavior,
corpora, tests) validate the absent substrate. The correct action is
to stop, keep the repository valid and green, record this preflight,
and extend the remediation chain.

What was deliberately **not** done: no trace/dashboard/finding/
correlation/Agent code was added; no dependency was introduced; no
version string changed; no migration was authored; no v0.0–v0.3 code
was rewritten; the dormant OTLP receiver spike stayed dormant and
disabled; no listener was started; no benchmark targets were declared
(WP15 forbids declaring them before the substrate exists to measure).
The only change in this session is this document.
