## Preflight decision (per milestone rules)

The v0.6 milestone rules distinguish narrow gaps ("fix narrow regressions
or small missing prerequisites … do not redesign completed … foundations")
from major prerequisites ("If a major prerequisite such as shared
Resource/Scope identity, immutable dataset revisions, authoritative query
semantics, typed attributes, **evidence/report revisioning, disclosure
projection, safe Agent registry extension**, workspace persistence, or
safe locking is absent, **stop before publishing metric data through an
incompatible parallel system**"), and additionally forbid silently
reimplementing v0.0 through v0.5.

The gaps found are not narrow regressions. They are two entire milestones
(v0.4 deterministic analysis, v0.5 Agent Query Interface) plus six-plus
unstarted v0.3 work packages. Three of the stop-rule's named major
prerequisites are absent outright (P14 report revisioning, P15 disclosure
projection, P16 Agent registry), alongside the inherited packaging debt
(P19):

| Missing capability | Milestone debt | v0.6 work it blocks |
|---|---|---|
| Shared disclosure/redaction projection | v0.3 W6 | WP6 report/bundle disclosure; WP7 disclosure-aware `metric.*` operations; governance of label values, Resource/Scope attributes, exemplar attributes and trace/span IDs, source paths, snapshots — building it inside v0.6 would create the forbidden second implementation |
| Report generation + exact report revisions | v0.3 W5 | WP6 metric evidence rendered into deterministic offline reports; e2e offline report |
| Portable `.logscope-case` bundle | v0.3 W7 | WP6 bounded metric data/evidence in bundles with full/subset/snapshot reproduction states; e2e bundle |
| Investigation/evidence/timeline UX | v0.3 W3/W4 | WP5 pin-to-investigation flows; WP6 evidence UX host surfaces; UI-side equivalence evidence |
| Deterministic analysis (patterns, comparison, correlation, findings) | all of v0.4 | WP6 deterministic pattern-count overlays; the mandatory e2e demonstration |
| Agent Query Protocol v1alpha1 (registry, envelopes, capability discovery, cursors, budgets, disclosure profiles, session/token model, audit, CLI, loopback HTTP) | all of v0.5 | **all of WP7** — the five `metric.*` operations must extend the existing registry additively; a metric-only protocol/CLI/HTTP/cursor/audit path is explicitly forbidden; cross-surface conformance tests have no second/third surface |
| Cross-process workspace locking (`workspace_busy` semantics) | v0.5 WP8 | CLI/HTTP metric access against an open desktop workspace |
| 5M benchmarks + reliability baselines | v0.3 W8 | WP9 metric benchmarks extend baselines never taken for evidence/report/bundle/Agent paths |
| v0.3/v0.4/v0.5 sweeps, acceptance matrices, releases | v0.3 W9/W-R, v0.4 WP9, v0.5 WP9 | v0.6 gate 1 ("actual v0.5 … acceptance report") and gate 2 ("existing valid v0.5 workspace" under a frozen released schema) |
| Graphical setup extractor + payload byte-equivalence | inherited v0.2 gate 19 | v0.6 packaging gates (both artifacts from one payload, metric parsers/schemas included in both) |

Of v0.6's work packages, WP6 (evidence/reports/bundles/overlays) and WP7
(Agent metric operations) have **no baseline to extend at all**; WP5
lacks its investigation host surfaces; and while WP1–WP4 (canonical
domain, static importers, quality engine, query service) could be built
mechanically, publishing metric datasets, evidence kinds, saved
definitions, and workspace migrations against evidence/report/bundle/
disclosure/Agent contracts that the v0.3/v0.4/v0.5 remediation will then
define would bake in exactly the incompatible parallel system the stop
rule forbids — schema v3 is still amendable, migration numbering below
`0004_analysis` is unresolved, and every metric evidence kind, report
renderer hook, bundle section, and Agent schema would be a guess frozen
by v0.6's own versioning rules. The correct action is to stop, keep the
repository valid and green, record this preflight, and extend the
remediation chain.

## Recorded repository facts and decisions for the resumed session

Verified repository facts (not design work), recorded so the resumed
milestone does not re-derive them:

- **`opentelemetry-proto` is pinned at 0.32.0** in the spike. The
  resumed WP1 must deliberately re-pin (keep or upgrade) and record the
  exact protobuf/OTLP/OpenMetrics specification revisions its fixtures
  and generated code target.
- **`datasets.signal` (`logs | metrics | spans`) is the capability
  seam** already present since schema v1; metric datasets extend it
  rather than introducing a parallel dataset concept.
- **Resource/Scope descriptors are already signal-neutral** — v0.6 must
  reference them, not copy them.
- **The spike store schema is not the contract.** `metric_writer.rs`
  flattens histogram/exemplar/quality payloads into JSON string columns;
  the v0.6 typed-column requirement supersedes it, and the milestone
  prompt authorizes discarding incorrect spike storage.
- **The rollup proof covers gauge + delta-sum only.** Cumulative
  rate/reset/gap semantics, histogram merge/percentile, exponential
  downscaling, and Summary handling are unwritten and belong to the
  resumed WP3/WP4 against the milestone prompt's semantics tables.
- **No OpenMetrics parser exists.** WP2's OpenMetrics 1.0 subset is
  fresh work; capture-time semantics for snapshots have no precedent in
  the tree.
- **Migration numbering is unresolved until v0.4 lands** (its plan
  reserves `0004_analysis`); the metric control-plane migration follows
  whatever the completed chain establishes.
- **GUI binary is `logscope.exe`; the CLI ships as a distinct binary**
  (`logscope-cli.exe` per the v0.5 record) — metric CLI operations ride
  on that binary when v0.5 exists.
- The v0.6 milestone prompt's budget table, operation semantics,
  quality-state taxonomy, and acceptance gates remain the specification
  for the resumed implementation; nothing was descoped by this record.

The plan sections the milestone contract requires for implemented work —
descriptor/stream/point/exemplar schemas; stream-identity and conflict
rules; the format-by-format import matrix; the operation-validity
matrix; temporality/reset/gap/overlap/duplicate/missing policies;
rollup/downsampling/percentile decisions; overlay/mapping semantics;
evidence/report/bundle integration; the Agent operation table; budgets;
benchmark environment — are intentionally **not authored in this
session**. They must be designed against the completed v0.3 disclosure/
report/bundle contracts, the completed v0.4 analysis identities, and the
completed v0.5 protocol registry; authoring them now would bake in
guesses that v0.6's own versioning rules then freeze. They are the first
deliverable of the resumed milestone (WP1 design pass), after
remediation.
