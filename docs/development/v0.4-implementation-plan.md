## Design pass (WP0 deliverable — the sections the first preflight deferred)

### Migration `0004_analysis` (workspace schema v4)

One forward-only transactional migration. STRICT tables; all timestamps
TEXT RFC 3339 UTC; all JSON columns validated at the service layer.

- `analysis_definitions` — definition_id (PK, `adef-<uuid>`),
  definition_schema_version (1), kind
  (`message_pattern|stack_fingerprint|comparison|correlation|finding_rules`),
  name, description, dataset_selection_json, query_text,
  query_language_version, query_fingerprint (nullable when all-data),
  time_strategy_json, field_selection_json (body/stack/grouping
  selectors), algorithm_id, algorithm_version, config_json
  (normalized), config_fingerprint (`acfg-<hex>`), masking_profile_json,
  thresholds_json, limits_json, created_at, updated_at, revision.
  History via the existing `record_history` discipline
  (entity_kind `analysis_definition`); editing bumps revision and never
  mutates completed runs.
- `analysis_runs` — run_id (PK, `arun-<uuid>`), definition_id + FK,
  definition_revision, semantic_fingerprint (`asem-<hex>`, deterministic
  — see identity rules), state
  (`pending|running|completed|cancelled|failed|stale`), dataset_revs_json
  (exact `[{dataset_id, dsrev}]`), query_fingerprint,
  query_language_version, bounds_json (concrete UTC-nanos intervals:
  analysis window, plus baseline/suspect for comparisons),
  algorithm_id/version, config_fingerprint, progress_stage,
  counts_json (accepted/excluded/untimestamped/invalid/truncated/
  sampled), started_at, finished_at, warnings_json, manifest_json
  (result summary + derived-data references + per-file checksums),
  error_json, invalidation_reason. Two-phase discipline: the row is
  inserted `pending` before any byte of derived data; finished exactly
  once; crash recovery (workspace open, step extending W8) finishes
  `pending|running` rows as `failed(job/interrupted)` and sweeps their
  staging directories. **Only `completed` runs are usable results;
  cancellation/failure/staleness is never an empty success.**
- `analysis_findings` — finding_id (PK, `afind-<hex>`, semantic — see
  identity), origin (`deterministic`; manual findings stay in
  `investigation_items` and are never rewritten), finding_schema_version,
  rule_id, rule_version, run_id + FK, subject_json (result identity),
  title, explanation, calculation_json (inputs+formula+thresholds),
  severity, severity_rule_json, confidence (nullable), contributing_json
  (bounded ids or reproducible scope), examples_json, state_json
  (exact/approximate/truncated + limitations), created_at (from run
  completion), revision. Re-evaluation inserts new rows keyed by a new
  run; rows referenced by evidence are retention-protected.
- `derived_artifacts` — artifact_id (PK), run_id + FK, kind
  (`pattern_membership|bucket_series|comparison_domain|correlation_edges`),
  rel_path (under `derived/analysis/<run_id>/`), row_count, byte_size,
  sha256, schema_version, created_at. Derived files are rebuildable,
  disposable, and never the only copy of anything canonical.
- Migration rollback safety: same policy as 0003 — single transaction;
  failure leaves schema v3 valid; `newer_database_is_rejected` continues
  to refuse future schemas. Existing manual items keep
  `authored_by_user=1` untouched (gate 3); no data rewrite.

### Deterministic identity and canonical serialization

- Canonical JSON serialization for identity input: object keys sorted
  lexicographically, arrays in documented order (dataset revs sorted by
  dataset_id; fields as selected order is part of config), no floats in
  identity inputs (thresholds serialized as decimal strings), UTF-8, no
  whitespace. One implementation in `logscope-case` (platform-neutral),
  property-tested.
- `semantic_fingerprint` = `asem-` + BLAKE3(canonical JSON of
  {dataset_revs, query_fingerprint, query_language_version, bounds,
  algorithm_id, algorithm_version, config_fingerprint}). Excludes run
  ids, timestamps, machine anything. Identical inputs ⇒ identical
  fingerprint ⇒ identical semantic result identities (a rerun creates a
  new `arun-` execution record with the same `asem-`).
- Pattern IDs: `pat-` + BLAKE3(canonical {algorithm_id,
  algorithm_version, masking_config_fingerprint, normalized_template}).
  Content-addressed; counts/examples/labels never affect the ID.
  Stack fingerprints: `stk-` + BLAKE3(canonical {algorithm_id/version,
  masking identity, exception_type, normalized_frames, cause_chain}).
- Comparison result IDs: `acmp-` + BLAKE3(canonical {semantic_fingerprint,
  dimension, key_identity, rule_id, rule_version}).
- Correlation edge/group IDs: `acor-` + BLAKE3(canonical
  {semantic_fingerprint, rule_id+version, normalized_key_or_temporal_rule,
  sorted participating canonical event IDs}).
- Finding IDs: `afind-` + BLAKE3(canonical {rule_id, rule_version,
  subject_semantic_id, calculation_identity}).
- Collision policy: full 32-hex digests stored; display may shorten to
  12 hex but every surface exposes copy-full-ID; the store refuses to
  merge rows whose full IDs differ (UNIQUE on full ID; a genuine BLAKE3
  collision fails loudly via constraint, never silently merges) — tested
  with crafted same-prefix IDs.

### Template extraction contract (WP2; ADR to be written with WP2)

Decision (recorded now, implemented in WP2): **pure rule-based masking
templates, no adaptive clustering.** Each record is independently
tokenized and masked by versioned deterministic rules; the template IS
the masked token sequence; the pattern is the set of records sharing it.
This is trivially order-independent (the prompt's randomized-partition /
parallelism determinism requirement), fully explainable (every mask rule
visible), and streams in one bounded pass. The known limitation —
messages differing beyond the mask rules form distinct patterns instead
of being fuzzily merged — is documented and honest; adaptive merge
(Drain-style trees) is insertion-order-dependent and is deliberately
rejected for v0.4.

- Unicode: NFC normalize; invalid UTF-8 already impossible post-ingest
  (canonical text). Case-sensitive by default (config flag to fold).
- Whitespace: runs collapse to one space for identity; line endings
  normalized to `\n`; leading/trailing trimmed. Multiline: first line is
  the message template; a stack-trace field goes to the stack
  fingerprinter, never mixed into the message template.
- Tokenization: split on whitespace; punctuation retained attached
  except bracket/quote pairs handled by the quoted-value rule.
- Built-in mask rules (each independently on/off, versioned as a set:
  `mask-set v1`): timestamp forms, UUID, trace/span hex IDs, IPv4/IPv6,
  `:port`, durations (`12ms`, `3.4s`), byte sizes, integers, decimals,
  0x-hex, file paths (slash/backslash heuristic), URLs, quoted values
  (`"…"`/`'…'` masked as one token), user-selected typed fields.
  Each masked token renders as `<num>`, `<uuid>`, `<ip>`, … in the
  template. Masking is analysis identity ONLY — the UI copy and ADR say
  explicitly it is not redaction.
- Bounds: max message length 8 KiB (longer: truncated-for-analysis flag
  on the pattern), max 512 tokens, max distinct patterns per run
  (limit, default 50k) → explicit truncated state.
- Missing/incompatible message field: excluded with counts; never an
  empty-template pattern.
- Examples: earliest, latest, peak-bucket, plus up to K distinct-resource
  examples; ties broken by canonical event ID ascending. All selection
  from data already streamed — deterministic.

### Stack fingerprint contract (WP2)

Parse per documented log-stack forms (Java, Python, Node, .NET, Go
panics) with a shared normalized frame model {module, function, location
(masked)}. Identity = exception type + ordered frames (line numbers and
addresses masked by rule) + nested-cause chain (bounded depth 8, frames
per trace 128, deeper: truncated flag participates in identity as an
explicit `+truncated` marker so a partial trace never collides with its
complete form). Malformed/partial traces fingerprint what parsed plus a
parse-quality state; distinct exception types never merge. Repeated
framework frames kept (no frame-dropping heuristics in v1; documented).

### Comparison decision table (WP3)

Classifications v1 (`cmp-rules v1`); all rates = count / duration in
seconds; different-duration windows classify on RATES only:

| Condition (after min-count guard) | Classification |
|---|---|
| baseline=0, suspect ≥ min_new_count | `New` |
| baseline ≥ min_base_count, suspect=0 | `Disappeared` |
| rate_change ≥ +threshold_rel or abs ≥ +threshold_abs | `Increased` |
| rate_change ≤ −threshold_rel or abs ≤ −threshold_abs | `Decreased` |
| within thresholds | `Unchanged` |
| below min counts both sides | `InsufficientData` |
| type conflict / cardinality guard / not in bounded union | `Excluded` (reason recorded) |

Zero-baseline relative change = `undefined` (never ∞/NaN — JSON gets the
string state, tested). Candidate domain = exact bounded union of both
windows' top-K by combined count (documented; never two independent
top-Ks), with explicit `Other` bucket and cardinality estimate surfaced
before expensive runs. Overlapping windows: refused by default; explicit
opt-in records overlap span and shared-record counts.

### Correlation model (WP4)

Confidence classes exactly as specified: `Exact` (canonical trace ID or
trace+span pair, validated at ingest; span-alone never exact),
`Correlated` (typed stable app/transport identifier, exact match on
canonical value; any normalization explicit+versioned), `Probable`
(documented resource/operation/time-proximity rule; always labeled
`Investigative lead only`). Candidate generation is key-partitioned
(never pairwise): group by validated key within time partitions, caps on
group size (default 256), groups per run (10k), edges per event (32),
total edges (250k), scanned records (limit from run config). Retry /
operational-duplicate / clock-skew / gap signals per the spec'd evidence
ladders — each a rule with ID+version whose reason lists matched and
missing fields. Ordering: event time then canonical event ID; missing
timestamps stay in an explicit undated bucket (never reordered by import
time).

### Deterministic findings (WP5)

Initial rule set (`find-rules v1`, each with thresholds in config):
new-high-severity-pattern, increased-error-pattern,
disappeared-pattern, repeated-retry-signal, operational-duplicate,
clock-skew-warning, concentrated-dimension-change. Severity = generic
mapping from canonical severity ceiling + magnitude thresholds
(documented table in the WP5 ADR); never customer/financial/security
impact claims; forbidden-wording test (`confirmed`, `root cause`,
`caused by`, `therefore`) over every generated string.

### Derived data ownership + invalidation (WP8 enforced from WP1)

Derived files live under `derived/analysis/<run_id>/` inside the
workspace, built in `staging/<job>/` and renamed at publish (same
pattern as imports). Stale when: dataset revision changed/disappeared,
query semantics or language version changed, bounds changed, algorithm/
rule version changed, masking/threshold config changed, derived file
missing or checksum-mismatched. Stale marks the RUN stale (live
references report it); history is never invalidated retroactively.
Cache reuse requires full identity verification (semantic fingerprint +
manifest checksums), never name/mtime. Retention: unreferenced runs are
deletable; runs referenced by evidence/reports/bundles are protected
(FK + check before cleanup). Recovery on open extends the W8 sweep:
interrupted runs → failed tombstones; orphan derived/staging swept;
corrupt manifests → run marked failed with reason.

### Integration design (WP6)

- Evidence: envelope **v2** adds `Pattern`, `ComparisonResult`,
  `Correlation`, `DeterministicFinding` reference+snapshot kinds; v1
  payloads decode unchanged (corpus already proves version gating).
  Resolution states extend the resolver vocabulary with
  `derived_rebuildable`, `analysis_stale`, `algorithm_unsupported`
  (registered in the error-code/vocab registries). Verification never
  reruns an analysis.
- Reports: new section kinds render analysis evidence with IDs,
  versions, formulas, thresholds, limitations; static tables only; the
  existing no-script/no-network HTML model and hostile-content proofs
  extend to templates/keys/examples.
- Redaction: the ONE projection gains awareness of analysis payloads
  (templates, examples, keys, configs are all snapshot JSON → already
  walked); preview==final stays byte-asserted.
- Bundles: analysis entries (definitions, completed-run manifests,
  bounded results) with per-analysis declared reproduction state
  (`full_within_scope|subset_only|snapshot_only`); importer preserves
  snapshot-only honestly when algorithm versions are unsupported; no
  SQLite files or raw cache directories in bundles.

### Risks

| Risk | Mitigation |
|---|---|
| Order-dependence sneaking into results via parallel merge | rule-based templates (order-free by construction); merge steps forbidden from data-dependent ordering; determinism tests run with randomized partition order + parallelism |
| Pattern cardinality explosion (mask rules too weak for a corpus) | hard distinct-pattern limit with explicit truncated state; cardinality estimate before run; mask preview shows change counts |
| Correlation edge blowup on hot keys | per-group/edge caps with truncation counts; high-cardinality guard refuses unbounded key domains |
| DuckDB float nondeterminism in aggregates | identity inputs exclude floats; rates computed in Rust from integer counts + integer nanos; documented decimal rendering |
| Derived cache divergence from SQLite truth | manifest checksums verified on use; rebuild path proven by test (delete cache → rebuild → identical result IDs) |
| Envelope v2 breaking v1 readers | version-gated decode already refuses newer versions honestly (corpus-proven); v1 kinds untouched |
| Report/bundle size growth with analysis content | bounded examples/top-K everywhere; byte limits in run config; truncation states rendered |
