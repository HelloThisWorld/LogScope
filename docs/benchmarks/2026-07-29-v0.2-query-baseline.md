# v0.2 Explorer query baseline — measured 2026-07-29/30

Machine: i9-12900KF (24 threads), 64 GB RAM, NVMe, Windows 11 Pro
10.0.26100. Build: release (rustc 1.97.1), commits of the
`feature/logscope-v0.0-v0.1` branch at the 0.2.0 preparation point.
Corpus: deterministic JSONL generator, seed 20260729 (8 services, 3
regions, ~7% ERROR / 12% WARN, ~10% trace ids, nested `http`/`k8s`
attributes, unique `seq`, rare token `cascade`, ~1% out-of-order
timestamps). Harness: `cargo run --release -p logscope-testsupport
--bin bench_query -- <count>` — real pipeline (import → publish → FTS →
catalog), then service-level query timing below Tauri.

Definitions: **cold** = first execution in the process (OS page cache
not dropped — machine-realistic, documented); **p50/max** = median/worst
of the 5 following runs. Pages fetch 200 rows.

PASS (≈20 ms).**

Scaling is linear with corpus size (each page/aggregate is one bounded
scan over the immutable segments; no result set is ever materialized in
the application). The 10M budget run was not executed this milestone:
at the measured linear scaling it would sit around 1.8 s/page, and the
roadmap ties 10M to a later milestone's segment-pruning work — recorded
here rather than fabricated.

Raw JSON for both runs is emitted by the harness (`JSON:` line) for
regression comparison.
