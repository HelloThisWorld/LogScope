# v0.0 performance baseline — 2026-07-29

Executed on this machine; no extrapolated numbers.

## Environment

- CPU: Intel Core i9-12900KF (24 threads) · RAM: 64 GB · Disk: NVMe (D:)
- OS: Windows 11 Pro 10.0.26100 · toolchain: rustc 1.97.1 (release build)
- State: warm OS cache (corpus generated immediately before import);
  fresh workspace per run (cold DuckDB/SQLite state)
- Harness: `cargo run --release -p logscope-testsupport --bin bench_import`
  · seed `20260729` (deterministic corpora, generated on demand, never
  committed)

## Results

| Run | Input shape | Import | Throughput | Peak WS | Output disk | Queries |

| `logs 1000000` | 1,000,000 JSONL records, 240.2 MiB, 8 services, ~10% traced, 1% out-of-order | 24.0 s | 41,658 rec/s | 175 MiB | 152.6 MiB (4 segments) | first page 261 ms · severity filter 233 ms · FTS 235 ms (20/20 expected hits) |

| `cancel-logs 1000000` | cancel issued at first progress event | — | — | 54 MiB | — | cancel latency **4.7 ms**, staging empty, no datasets leaked |

## Interpretation

- **Bounded memory**: logs peak (175 MiB) is below the input size
  (240 MiB); metrics peak is dominated by fixed Parquet row-group buffers
  and is scale-invariant (513 MiB at 1M vs 489 MiB at 250k points — 4×
  input, ~5% peak change). No path loads a complete input.
- **Cancellation** is effectively immediate (cooperative checkpoints per
  batch) and leaves the workspace clean (verified by the harness).
- Raw JSON lines: the harness prints `RESULT_JSON:` records; this table
  transcribes them verbatim.

Provisional budgets derived from these numbers live in ADR-0010.
